# StreamNest

StreamNest 是一个面向授权与公开内容的本机「在线视频下载管理器」。下载 Windows 便携版并解压后，双击 `启动StreamNest便携版.cmd`，浏览器会打开 `http://localhost:3000/`；不需要租服务器、安装 Node.js 或 Python。**请先解压，不要在 ZIP 内直接运行。**

- `app/`：下载任务管理界面，只在本机打开。
- `backend/`：实际解析与下载服务，便携版已打包运行环境。
- 抖音和快手目前依赖单独的本机下载核心，**未包含在便携版内**。没有该核心时其他平台仍可使用，但抖音/快手会提示服务离线。

Windows 用户请从 GitHub Releases 下载 `StreamNest-Windows-x64-*.zip`，按 [`README-便携版.txt`](./README-便携版.txt) 启动；源代码用户见下文“从源代码运行”。便携版会把文件保存到解压目录下的 `下载内容/`。这些服务仅监听 `127.0.0.1`，不能把这个本机网址直接发给其他人使用。

## 已实现

- 31 个国内外平台的链接域名识别；历史验收中 23 个曾完成真实媒体与图片完整下载，另有 2 个完成公开媒体流与图片解析验证。这不是当前可用性保证，最新复验见下文。
- 从实际视频页读取标题、作者、时长、缩略图和可用格式。
- 视频、MP3、封面原图与视频首帧格式选择；没有公开封面的内容会自动提供首帧图片。抖音图文作品和可公开读取的小红书图文笔记支持全部图片、逐张选择与多选 ZIP；只选一张时直接保存图片，选择多张或点击“一键下载全部”时生成按顺序编号的 ZIP，避免浏览器拦截连续下载。小红书图片使用平台公开返回的尺寸，不能保证每篇笔记都提供无压缩原图。
- 图片和媒体文件都通过短时下载凭证保存，并由本机后台直接写入项目根目录的 `下载内容/` 文件夹，不经过浏览器下载或 IDM；遇到同名文件时会自动添加编号，不覆盖已有内容。过期文件、已交付的国内平台内部副本，以及服务重启遗留的孤儿临时目录都会自动清理。
- 默认只解析公开、无需登录的内容；私密、无权限、直播和 DRM 内容仍会拒绝。B 站另有需用户主动启用的本机会话模式，见下文。
- 默认不接收浏览器 Cookie；仅在用户于本机主动点击 B 站会话同步后，浏览器助手才向本机解析服务传递 B 站域名 Cookie，并只保存在内存中（最多 8 小时）。应用仍限制文件大小、视频时长、请求频率和同时下载数，也不接受用户输入的 IP/内网媒体地址。
- 18+ 平台年龄确认、本机任务队列、任务筛选、格式详情和响应式界面。

## 从源代码运行

源代码运行需要 Node.js 22.13+、Python 3.11+ 和 FFmpeg。Windows 上可以双击项目根目录的 `打开StreamNest统一下载管理器.cmd`；它会在后台启动网页与通用解析服务。若本机另有兼容的抖音/快手核心且已设置 `STREAMNEST_CORE_DIR`，也会尝试启动该核心。便携版用户应使用 `启动StreamNest便携版.cmd`，不要使用此源码启动器。

### 可选：使用自己的 B 站会员会话

只有需要解析自己有权观看的 B 站会员视频时，才需要浏览器助手。请在 Edge 的 `edge://extensions/` 页面手动重新加载“StreamNest 浏览器助手”，确认版本为 `0.3.6`，并在浏览器询问时确认 B 站和本机服务权限。然后刷新 `http://localhost:3000/`，粘贴具体的视频或番剧单集链接，点击“同步 Edge B 站会话”。若网页未检测到助手，可直接点击 Edge 工具栏中的助手图标，在弹窗点击“同步本机 B 站会话”。新版弹窗会显示“助手版本 0.3.6，已就绪”；待页面显示同步成功后重新解析，再选择实际列出的画质。B 站任务会默认选择实际解析到的最高画质；若只显示 480P，说明目前未拿到更高清晰度，并非旧文件可以无损提高。扩展安装与重新加载步骤见 [`browser-helper/README.md`](./browser-helper/README.md)。

会话只用于本机 B 站请求，不会写入网页任务记录；可在网页点击“断开 B 站会话”，重启解析服务也会清除它。不要在聊天中发送账号、密码、验证码或 Cookie。能在播放器中观看不等于一定能保存：会员画质可能受平台接口或 DRM 限制，只有完成真实文件下载并验证媒体字节后才能算成功。本机已对 `ep826497` 完成真实 2160P（3840×2160）MP4 下载验证，包含 H.264 视频和 AAC 音频；其他视频是否提供 4K，以当前账号实际返回的非 DRM 媒体流为准。

### 其他平台的最高画质

网页默认选中本次解析实际返回的最高分辨率，并提供“选最高分辨率”和“选快速版本”快捷按钮；同分辨率若有快速合并流和更高码率的视频流，会保留两种选择并优先选后者。站点没有提供分辨率时，网页会明确显示“未返回可核实的分辨率”，不会将码率或自动画质冒充 1080P/4K。竖屏视频按短边标注画质，同时在格式详情显示原始宽高。链接输入框下方可展开 31 站识别清单；识别域名不代表任何作品都可下载。通用平台和 B 站的默认单文件上限均为 8 GiB，可分别用 `STREAMNEST_MAX_FILE_SIZE_BYTES` 与 `STREAMNEST_MAX_BILIBILI_FILE_SIZE_BYTES` 调整。这个上限不会让平台生成原本不存在的画质；DRM、登录或站点人机验证仍不会绕过。逐站实时核查与完整下载验收的区别见 `PLATFORM_VALIDATION.md`。

2026-09-28 的当前样本巡检：30 站中 20 站返回视频、1 站只返回音频、9 站未能解析；小红书缺可公开读取的单篇链接，未计入。B 站本机会话在这次巡检时未同步，抖音／快手独立核心目录已缺失。逐站结果与本轮样本画质见 [`PLATFORM_VALIDATION.md`](./PLATFORM_VALIDATION.md)，不能将一次样本结果视为全站最高画质或完整下载保证。

### 视频下载线路稳定性

通用下载链路对暂时性 HTTP 与 HLS 片段错误做有限重试；任何片段仍不可用时会报错，不会把缺片的视频标成下载完成。TED、Vimeo、Beeg、XMoviesForYou、海角网等由公开页面提供短时效媒体地址的平台，在地址明确过期时仅重新解析**同一视频、同一格式 ID 和画质标签**，绝不自动改选低画质。HQPorner、SxyPrn 的直连 MP4 会核对服务器返回的字节范围与文件总长度；浏览器助手捕获的抖音、快手 MP4 会核对已知的文件总长度。线路更换不等于突破站点的登录、付费、DRM、地区或人机验证限制；无法安全确认媒体身份与完整性时，请重新打开原视频页解析。

红果短剧使用同一网页，粘贴 `https://hongguoduanju.com/player/7684649550316833817` 这种**单集**链接；首页、剧集列表不代表具体一集。该站当前公开 MP4 不提供分辨率元数据，因此界面显示“站点公开画质”，不会虚构 1080P/4K。是否可保存以该集当前公开、非 DRM 播放流和实际下载结果为准。

2026-09-28 的综合优化让画质列表按视频分辨率、音频、图片排列，并在当前选择旁显示编码、估计大小和 AI 放大提醒；“最高分辨率”不再误称为原生最高画质。下载面板显示已接收字节数，即使总大小未知也不会只显示误导性的 0%。普通平台的解析仅对 500/502/503/504、超时、连接重置等临时故障增加一次重试；403、需要登录和验证不会重复请求。HQPorner/SxyPrn 的 MP4 Range 在完整快速响应后由 1 MiB 渐进增至最多 4 MiB，慢响应则缩回，既减少顺畅线路的请求开销，也保留慢线路的及时进度反馈。实际吞吐仍受源站、网络和选定画质影响，没有固定提速保证。

可读取的详情页会列出各段公开视频；下载前验证 HLS 清单和媒体域名，标准公开 AES-128 HLS 可以保存，DRM、登录/付费限制、不可公开读取的播放密钥以及未经核验的跳转会被拒绝。站点偶尔返回 403 时，请稍后重新解析，不会绕过人机验证或读取该站浏览器 Cookie。只有真实媒体文件检查通过才算下载成功。

下面是需要分别调试服务时使用的手动方式。

Web 应用需要 Node.js 22.13 或更高版本：

```bash
npm install
copy .env.example .env.local
npm run dev
```

解析服务需要 Python 3.11+ 和 FFmpeg：

```bash
cd backend
python -m venv .venv
.venv/Scripts/pip install -r requirements-dev.txt
.venv/Scripts/python -m uvicorn streamnest_api.main:app --host 127.0.0.1 --port 8788
```

macOS/Linux 上将 `.venv/Scripts/` 替换为 `.venv/bin/`。

## 检查

```bash
npm test
npm run typecheck
npm run lint
cd backend
.venv/Scripts/python -m pytest -q
```

在三个本机服务已经启动时，可运行完整真实平台验收。该命令会实际下载每个平台的低流量媒体格式和图片，并把结果写入 `work/platform-validation-results.json`：

```bash
npm run test:platforms
```

也可以只回归一个平台，例如：`npm run test:platforms -- Dailymotion`。单项结果会写入带平台名的独立文件，不会覆盖 `work/platform-validation-results.json` 中的完整验收记录。

需要做长时间运行检查时，可指定结束时间启动健康监测。监测器每 30 秒检查三个本机服务，并在异常时使用统一启动器恢复：

```bash
npm run monitor -- --until=2026-08-23T07:00:00+08:00
```

## 制作 Windows 便携包

在已安装 Node.js、Python 和 FFmpeg 的构建机运行 `npm run build:portable`。脚本执行类型检查、网页构建、后台 EXE 打包，复制运行环境、第三方许可证和对应的 FFmpeg 源码归档，再在 `outputs/` 中生成 ZIP 与 SHA-256 校验值。构建产物、运行日志和用户下载内容都被 `.gitignore` 排除，不应提交到仓库。第三方组件的许可证见 [`THIRD_PARTY.md`](./THIRD_PARTY.md)。

平台规则会持续变化。名单只表示已实现链接识别，最终是否可用以当次解析结果为准。历史验收曾覆盖 YouTube、Bilibili、X、TED、微博、Facebook、Reddit、AcFun、XVideos、Pornhub、Eporner、XNXX、Rule34Video、Beeg、SxyPrn、抖音、快手、Dailymotion、TikTok、Instagram、Twitch、SoundCloud 和 Pinterest 的媒体与图片；不能据此保证今天全部仍能下载或仍有相同最高画质。2026-09-27 的最高画质复验中，YouTube、X、Reddit、Beeg、TED、Eporner、XNXX、Rule34Video、TikTok、微博、Facebook、AcFun、XVideos 和 Pornhub 已通过完整文件检查；Pornhub 的 720P 曾失败一次，随后复验通过，稳定性仍需观察。抖音和快手当前因独立本地核心目录缺失而不可用，SpankBang 当前要求站点人机验证。各站当次结果及“解析/媒体字节/完整下载”的证据分级见 [`PLATFORM_VALIDATION.md`](./PLATFORM_VALIDATION.md)。

## 使用边界

StreamNest 不绕过 DRM、无权限的登录或付费墙、地区限制及其他访问控制。仅保存用户自己拥有、已获授权或平台允许保存的内容；可选 B 站会话模式只使用用户在本机已登录且有观看权限的账号，不能保证每条会员视频可下载。
